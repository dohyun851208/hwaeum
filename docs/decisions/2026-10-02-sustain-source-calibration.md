# 지속음 접합·음별 원음 선택·조율 보정 통일

2026-10-02 · 구현 완료 · [수정 전 조사와 검토](../plans/2026-10-02-sustain-pitch-preparation.md)

> 이 문서는 `f5f31bc` 초기 구현의 기록이다. 전환 페이드·입력 체류·포락선 보정·첫 어택·해금 연결은 [후속 결정](2026-10-02-natural-melody-transitions.md)에서 수정했다. 아래 음량 표는 당시 80ms 처리의 결과이며 현재 품질 기준이 아니다.

## 결정

관악·찰현 12종은 같은 칸을 유지하는 동안 소스 하나를 반복한다. 다른 칸으로 이동하면 그 음에 맞는 원음을 선택해 40ms 동안 겹쳐 연결한다. 새 발음은 안정 구간에서 들어오므로 원음 어택을 반복하지 않는다. 각 소스의 배속과 음별 게인은 해당 원음에 고정한다. 가야금은 한 번 뜯은 소리의 자연 감쇠를 유지한다.

그리기·저장 획·음표 재생·플레이헤드 탐색·오프라인 렌더에서 같은 샘플 선택, 조율, 루프 준비 함수를 쓴다. 레시피 형식과 서양 15칸/국악 10칸 좌표는 바꾸지 않았다.

### 루프

- `findStableLoopRegion`은 0.9초 최종 루프 + 최대 80ms 페이드 + 40ms 정렬 여유를 합한 1.02초 안정 구간을 우선 찾는다.
- 안정 구간 `[A,B)`에서 돌아갈 위치 `R` 앞의 페이드 `[R−F,R)`와 끝 페이드 `[E−F,E)`를 확보한다. 뒤의 마지막 프레임은 정확히 `R−1` 프레임이 된다. 어택·무음을 앞 재료로 섞지 않는다.
- 실제 페이드 창 전체와 모든 채널의 상관을 기준으로 끝점을 안정 구간 안에서 정렬한다. 같은 정렬을 모든 지속음에 적용한다.
- 동위상에서는 합이 1인 페이드, 무상관에서는 등전력 보정을 사용한다. 음의 상관을 추가 증폭하지 않는다. sin/cos를 동위상 신호에 그대로 더해 생기던 +3dB 봉우리를 없앤다.
- 녹음의 느린 감쇠가 반복마다 되살아나는 맥동은 80ms RMS 창의 완만한 공통 진폭 보정으로 완화한다. 보정 전후 안정 구간 평균 에너지를 보존하며 스테레오 채널의 상대 위상·음량도 유지한다. 음별 출력 게인 한도를 넓히는 처리가 아니다.
- 원음이 짧으면 페이드를 20ms까지 줄여 길이를 확보한다. 그래도 부족한 후보는 짧은 루프로 남긴다. 루프를 늘리기 위해 배속을 잘라 음정을 바꾸지 않는다.

기존 `findStableLoopRegion`의 기본 API는 유지했다. 엔진·측정 도구는 정렬 전 안정 구간을 받은 후 새 `sustainLoopFrames`/`crossfadeSustainLoop` 경로를 쓴다. 준비된 버퍼는 원음 버퍼별로 캐시한다.

### 원음·음정·음량

- `audio-plan.js`의 `sampleVoiceRuns`는 같은 음의 연속 이벤트를 하나로 묶는다. 획 시작 파일을 끝까지 4배속으로 끌고 가지 않는다.
- `minRate/maxRate`는 후보 소스 선택 조건이다. 재생 배속 자체를 제한하지 않는다. 범위 안 후보가 없으면 가장 가까운 파일을 정확한 목표 음정으로 재생한다.
- 로딩 중에는 기존 발음을 유지하고, 준비된 파일로 교체한다. 같은 요청은 합치고, 빠른 왕복·펜 떼기·정지로 무효화된 요청은 토큰으로 버린다. 새 악기의 다른 원음도 미리 디코드한다.
- `sample-calibration.js`는 체크인된 MP3의 실제 반복 구간에서 측정한 원음 Hz를 저장한다. 악기 공통 cents와 파일별 잔차도 진단 자료로 기록한다. 런타임 기준은 실제 Hz 하나이며, 기존 차용 `cents`와 별도의 `tuningCents`로 적용하므로 반음 차용 보정을 덮어쓰거나 두 번 적용하지 않는다.
- ±25% 예상음 검색만으로 조율을 확정하지 않는다. 넓은 YIN 탐색과 배음 검증을 병행하고, 높은 주기성·배음 근거가 없는 값은 자동 적용을 거부한다. 비브라토의 중심을 보정하며 순간 음정을 평탄하게 만들지는 않는다.
- 음별 게인은 새로 구운 루프 RMS로 다시 측정했다. 악기 평균을 보존하면서 ±3dB 한도를 유지한다. 더블베이스만 기존 ±12dB 예외를 유지하며, 이 예외를 자동 루프 명단과 분리했다. 가야금의 음별 게인은 1이다. 악기 간 음량 기준은 바이올린이다.
- 소금·대금·해금의 라이브에도 전체 재생과 같은 국악 저역통과 필터를 적용한다.

### 탐색·종료·가야금

일시정지/재개는 기존 컨텍스트와 소스를 유지한다. 위치부터 새로 재생할 때는 원래 이벤트 시각을 보존해 같은 원음을 선택하고 경과 배속을 적분한 위치로 진입한다. 진행 중인 40ms 전환도 복원하며, 탐색 시작의 클릭 방지를 위해 5ms 진입 페이드를 둔다. 브라우저의 소스 시작 위치 양자화·필터 초기 상태 때문에 전체 렌더를 잘라낸 PCM과 샘플 단위로 같다는 계약은 두지 않는다.

가야금은 원래 음 구간 뒤까지 분석해 첫 발음 RMS 대비 −42dB 이하가 200ms 유지되는 끝을 찾는다. 다음 매핑 발음 50ms 전과 최대 6초를 경계로 둔다. 분리한 버퍼 끝에 60ms 페이드를 구워 두 경로가 공유한다. `start(when, offset, duration)`의 duration은 **버퍼 내용의 초**로 제한하고, 종료 예약은 그 길이를 실제 배속으로 나눈 시간에 맞춘다. 수평 유지 중 재발음하지 않으며, 음 변경/새 획은 새로 뜯는다. 펜을 떼어도 자연 잔향은 남고 전체 정지는 잔향까지 정리한다.

Web Audio 명세: [루프](https://www.w3.org/TR/webaudio-1.0/#looping-AudioBufferSourceNode), [start의 offset·duration](https://www.w3.org/TR/webaudio-1.0/#dom-audiobuffersourcenode-start).

## 비교와 검증

기준선의 수평 획도 이미 소스 하나였다. 반복 어택처럼 들린 원인은 잘못 연결한 파형과 반복되는 감쇠였다. `[S−F,S)`를 무조건 섞는 수정은 자동 검출 구간 앞의 무음·어택을 포함하므로 채택하지 않았다. 한 파일을 계속 배속하는 방법은 도착 칸의 게인과 파일이 어긋나고 탐색 지점에 따라 음색이 달라지므로 교체했다.

- 단위 테스트 336개 통과. 접합 프레임·평균 에너지·스테레오 보존·자연 감쇠·음 이동의 보정·비동기 취소·탐색 위상 회귀를 포함한다.
- `node tools/smoke.cjs` 통합 검사 통과. 화면·저장 좌표 규칙 유지.
- Chrome 실제 디코드/OfflineAudioContext, **44,100Hz와 48,000Hz 각각 170칸 × 미리듣기/저장 획** 검사. 좌표/음높이 매핑 불일치 0, 수평 획 소스 수 모두 1. 160개 지속음은 두 경로의 루프 구간이 일치한다.
- ffmpeg 44.1/48kHz로 별도 재현한 엔진 버퍼에서도 접합의 2차 차분이 루프 내부 최댓값을 넘는 칸은 각각 **0/160**이다. 이는 수치 검사이며 단독으로 청감 합격을 뜻하지 않는다.
- 당시 보정값 생성에 사용한 분석기로 다시 재면 두 샘플레이트 모두 170칸의 중심값이 ±10센트 안에 있었고 최대 절댓값은 약 5.4센트였다. **독립 검증이 아니므로 170칸 모두 검증 완료라는 결론은 철회한다.** 사용자 제공 외부 검토 결과는 **161칸 ±10센트 이내, 9칸 판정 불확실**이다. 이 외부 검토의 전체 스크립트·칸별 판정표는 이번 저장소에 없으므로 여기서 재현한 독립 검증으로 표기하지 않는다. 자연 비브라토의 순간 음정을 평균율에 고정하는 목표도 아니다.

- 실제 캔버스에서 바이올린·단소·가야금의 자유 그리기와 음악에 맞춰 그리기: 같은 높이를 유지할 때 생성 1회, 펜 떼기 정상.

- 전체 오프라인 그래프와 MediaRecorder로 단소 전환을 WebM/Opus 스테레오 48kHz로 내보냈다(53,482바이트). ffprobe 확인, 브라우저 오류 0.

**남는 원음의 한계:** Chrome 48kHz에서 출력 배속까지 적용한 반복 길이가 0.9초 미만인 칸은 플루트 62/71, 오보에 64, 바이올린 57/69/71/76, 비올라 74, 첼로 74, 더블베이스 72다(0.55~0.88초). 클릭·주기적 음량 꺼짐은 줄었지만 짧은 녹음의 비브라토 패턴이 반복될 수 있다. 사람의 청취 평가를 수행했다고 주장하지 않는다. 더 긴 원음 교체가 필요할 때 이 목록부터 비교한다.

## 재측정과 적용 방향

```powershell
node tools/measure-sustain.cjs "$env:TEMP/hwaeum-calibration" --uncalibrated
python tools/calibrate-sustain.py "$env:TEMP/hwaeum-calibration" --write
npm run measure:loudness -- --notes
npm test
node tools/smoke.cjs
```

측정은 ffmpeg, 조율 분석은 Python numpy/scipy가 필요하다. 앱에는 추가 런타임 의존성이 없다. Node VM 검사와 Chrome 실제 렌더 검사는 별개다. `measure-sustain.cjs`는 칸별 파일·배속·루프·접합 곡률 지표와 PCM을 지정 폴더에 내보낸다. `calibrate-sustain.py`는 `--write`가 있을 때만 조율 모듈을 갱신한다.

서양 원본 WAV 아카이브는 이 PC에 없어 기존 큐레이션 도구로 파일을 다시 고르지 않았다. 재측정 도구는 저장소의 MP3만으로 동작한다. 원음 MP3를 수정하거나 교체하지 않았고 배포도 하지 않았다.

이번 상세 Chrome 결과는 로컬 임시 폴더 `hwaeum-sustain-audit-20261002` 아래 `browser-44100/`, `browser-48000/`, `ui-after/`, `final-measure/`에 있다. 임시 PCM은 git에 포함하지 않는다.
