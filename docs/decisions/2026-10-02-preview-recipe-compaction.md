# 펜 미리듣기의 획 처리 제거와 레시피 좌표 압축

2026-10-02 · [자연스러운 음 전환](2026-10-02-natural-melody-transitions.md)의 후속 최적화

## 결정

펜 시작·이동은 현재 악기·음계·버전·배경·길이·모드만 담은 작은 레시피를 전달한다. 저장 획, 그림, 공유 메타데이터는 조회하지 않는다. 전체 재생·저장·내보내기·공유는 기존 전체 레시피를 사용한다. 악기 음원 준비에도 같은 작은 레시피를 쓴다.

전체 레시피의 선율 좌표는 기본적으로 소수 다섯째 자리로 반올림한다. 음 경계 전후의 점은 계속 보존하며 점 수 제한을 다시 강제하지 않는다. 기존 레시피 형식·코덱은 그대로 유지한다.

- y 반올림으로 발음할 칸이 달라지면 해당 y는 원래 값을 유지한다. 국악의 발음 가능 여부도 같은 음높이 계산으로 확인한다.
- x 반올림 전후를 실제 획 재생 계획과 70ms 체류 필터에 넣어 비교한다. 소스의 음 순서·개수, 무음 구간 분리, 발음 시작/종료의 허용 오차가 달라지면 그 획의 x는 원래 값을 유지한다.
- 5분 작품에서 개별 시점의 최대 반올림 오차는 1.5ms, 두 시점 간 길이 오차는 3ms다. **70ms 바로 근처에서는 이 작은 오차도 판정을 바꿀 수 있다.** 따라서 무조건적인 반올림은 채택하지 않았다. 긴 작품도 고정된 시간 허용치를 가정하지 않고 작품 길이에 따른 오차를 사용한다.
- 이 압축 검사는 전체 레시피를 만들 때만 수행한다. 펜 이동 중에는 실행하지 않는다.

## 비교와 검증

기존 펜 콜백은 매번 `buildRecipe()`를 호출했다. 음 경계를 보존하는 정리뿐 아니라 엔진의 기존 획 재생 계획까지 불필요하게 만들었다. 실제 Chrome에서 12개 획·4,116개 점의 별도 합성 그림으로 `579aa6c`와 비교했다. 사용자 보고에 사용된 원본 그림은 제공되지 않았으므로 같은 입력이라고 주장하지 않는다.

- 수정 전 미리듣기 콜백+계획 생성 중앙값 약 8~9ms, 획 관련 조회 4회, 획 음높이 계산 7,191회/이동이었다. 수정 후 해당 조회·계산은 모두 0회이며 기존 획 재생 계획도 비어 있다. 측정은 비동기 음원 로딩과 캔버스 렌더 시간을 제외한다. 타이머에서 0ms로 관측된 값을 전체 입력 비용이 0이라는 뜻으로 해석하지 않는다.
- 같은 그림의 공유 주소 길이는 약 20.2만 자 → 11.0만 자(약 46% 감소), 보존한 점 수는 3,075개로 같다. 발음 MIDI 순서와 레시피 코덱 왕복도 일치했다. 주소 길이는 그림의 복잡도와 포함된 메타데이터에 따라 달라진다.
- 단위 회귀 348개와 통합 스모크를 통과했다. 서양·국악 음높이 경계 양쪽, 5분 작품의 70ms 인접 구간과 가까운 점 병합, 링크 축소·코덱 왕복을 검사한다. 통합 스모크는 펜 시작/이동이 획 조회를 시도하면 실패하도록 검사한다. 실제 Chrome 48kHz에서도 자유/음악에 맞춰 그리기의 떨림·저장 재생, 해금 탐색, WebM 내보내기 검사를 통과했다.

## 적용과 재현

`studio.js`에서 미리듣기 레시피를 분리하고 `audio-plan.js`의 순수 함수 `compactStrokePoints`로 압축 전후의 재생 의미를 확인한다. 기존 [좌표 정밀도 보존 결정](2026-10-02-natural-melody-transitions.md)은 위 조건부 반올림으로 보완한다.

로컬 서버에서 `npm test`, `node tools/smoke.cjs`, `node tools/verify-preview-recipe.cjs 579aa6c`로 재현한다. 브라우저 도구는 별도 Playwright·Chrome이 필요하며 `PLAYWRIGHT_MODULE`·`CHROME_PATH`로 경로를 지정할 수 있다. 결과는 git/배포에서 제외되는 `output/preview-recipe-review/results.json`에 저장된다.
