# 스튜디오: 밤의 벽에 건 한지 작업판

확인일: 2026-10-04

## 결론

사용자 의견 두 가지가 이어졌다.

1. 메인(랜딩)과 화음 갤러리는 디자인 톤이 비슷한데, 스튜디오는 색감이 붕 뜬다. 지금보다 어둡게 가야 할 것 같다.
2. 스튜디오 전체를 밤으로 바꾸자, 안쪽이 너무 어두워서 가독성이 확 떨어진다. 화음 갤러리에서는 좋았는데.

갤러리는 그림이 주인공이고 글이 적어서 어두운 벽이 어울린다. 스튜디오는 학생이 설명을 읽고, 메모를 적고, 칸을 고르는 곳이라 글이 많고 작다. 그래서 **바깥은 메인·갤러리와 같은 밤, 안쪽 작업판은 밝은 한지**로 나눈다. 갤러리가 어두운 벽에 밝은 작품을 거는 것과 같은 원리다. 문구·마크업 구조·배치는 그대로다.

- **벽**(바탕·머리·출처 줄): 메인·갤러리 로비와 같은 먹색(#101d20 → #0a1416)에 옅은 한지 결과 위쪽의 은은한 금빛을 둔다. 로고는 크림, 「스튜디오」는 금빛이다.
- **단계 줄**: 벽 위에 둔다. 지난 단계는 금빛 고리와 금선, 지금 단계는 크림으로 채운 원과 굵은 크림 글씨, 다음 단계는 흐린 고리다. 글자 대비는 모두 4.5:1 이상이다(다음 단계 7.2:1).
- **판**: 단계마다 한 장의 밝은 한지다. 위쪽이 조금 더 밝아 등불이 위에서 비추는 느낌이다(#fdfaf3 → #f5efe2). 테두리는 갤러리 표지와 같은 얇은 금선이고, 벽에 걸린 깊은 그림자를 둔다. 판 안의 카드·칸·도화지는 예전 밝은 스튜디오와 같다.
- **판 위 흐리던 글자**: 판에서는 금빛 작은 글씨(「1단계」)를 진한 금 #84652c로 바꿨다. 무드 색(회색이면 2.9:1)을 따르던 갈래 이름(분위기·관악기…)과 작품 단어도 같은 금빛으로 바꿨다. 도움말 회색은 #6b6f68→#61655e, 오류 글자는 #c4483a→#b23c2f로 조금 진하게 했다. 계이름은 제 색에 먹을 20% 섞었다(노란 「미」 2.6:1). 「선택한 부분 듣기」 글자는 먹색이다.
- **공유 창**: 창은 한지 그대로 두고, 뒤의 막은 갤러리 작품 보기처럼 먹빛이다.

## 비교

| 방식 | 판단 |
| --- | --- |
| 밝은 한지 작업실(10-03 리뉴얼) | 읽기는 좋지만, 메인과 갤러리 사이에서 혼자 낮이라 붕 뜸 |
| 먹색 머리띠 + 밝은 바탕(10-03 첫 판) | 띠만 검고 나머지 바탕이 밝아 위아래가 따로 놂. 단계 글씨도 흐렸음 |
| 스튜디오 전체 + 도화지까지 밤(이날 첫 시도) | 메인과는 하나가 됐지만, 글이 많은 판 안이 어두워 가독성이 크게 떨어짐. 커밋하지 않았고, 작업한 PC의 `output/night-studio/full-night.patch`(git 제외)에만 남김 |
| 밤의 벽 + 밝은 한지 판 | 채택. 바탕 전체가 먹빛이라 판이 벽에 걸린 작품처럼 읽히고(띠가 아님), 읽고 쓰는 면은 밝음 |

10-03 첫 판의 실패는 띠만 어둡고 바탕이 밝았던 탓이다. 이번에는 바탕 전체가 먹빛이라 판의 위·양옆·아래를 모두 감싼다. 단계 글씨는 크림 위계로 대비를 재서 맞췄다.

## 적용 방향

- 모든 변경은 `styles.css`의 `@renewal-2026-10` 구간에 있다.
  - 색 변수를 두 겹으로 둔다. `body:not(.channel-body)`에는 벽(밤) 값, `body:not(.channel-body) :is(.screen, .publish-modal)`에는 판(한지) 값이다. 이름이 같아서, 판 안의 기존 규칙(`var(--ink)`·`var(--canvas)`…)은 고치지 않아도 밝은 값을 그대로 읽는다.
  - `color`는 값으로 상속되므로 판이 `color: var(--ink)`를 직접 다시 정한다. 판은 `color-scheme: light`, 벽은 `dark`다. 그래서 판 안의 범위 막대·입력칸은 밝게, 페이지 스크롤 막대는 어둡게 나온다.
  - 바뀐 규칙은 지난 단계·지금 단계 표시(금빛·크림 채움), 판의 바탕·테두리·그림자, 금빛 작은 글씨와 흐린 글자 몇 가지, 공유 창의 막뿐이다.
- `studio.html`: `<meta name="color-scheme" content="dark">`를 넣어 스타일이 오기 전에도 흰 화면이 번쩍이지 않게 했다. 스타일시트 버전은 `20261004-night-wall`이다.
- 도화지·내보내기·악기 색·스크립트는 바꾸지 않았다. 전체 밤 시도에서 바꿨던 렌더러·악기 색은 되돌렸다.
- 갤러리는 바뀌지 않는다. 갤러리 로비와 메뉴를 변경 전 `styles.css`와 비교하니 바뀐 픽셀이 0이었다.
- 검사:
  - 화면에 보이는 모든 글자의 대비를 재는 스크립트로 확인했다. 대상은 다섯 단계·예시 답안·찍은 도장·소리 추가 카드·빠진 칸·공유 창, 화면 크기는 1280×720·1440×900이다.
  - 판 밖에 밝게 남은 곳은 없다.
  - 4.5:1에 못 미치는 것은 ▶·×·# 아이콘뿐이다. 예전 밝은 스튜디오에도 있던 것이다.
  - `npm test` 377개와 `tools/smoke.cjs`가 통과했다.
- 남은 일(이번 범위 밖): 소리 추가 카드 안의 칸 이름(사용할 부분·삭제·시작/끝, 11.5~12.5px)과 단어 칩(13px)이 14px 바닥보다 작다.
