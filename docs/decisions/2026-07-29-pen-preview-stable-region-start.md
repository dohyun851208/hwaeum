# 펜 소리는 샘플 어택을 기다리지 않고 안정 구간에서 시작한다

확인일: 2026-07-29

## 결론

라이브 드로잉 미리듣기(펜 소리)는 **서양 멀티샘플에서만** 파일 맨 앞(어택)이 아니라
지속음 루프의 안정 구간(`loopStart`)에서 재생을 시작한다. 전체 재생은 그대로 어택부터 —
자연스러운 발음은 곡에서 살리고, 펜은 즉답을 준다.

**국악 음원은 제외한다.** 소금 20ms · 대금 10ms 로 이미 즉각 발음되고, 시김새·발음이
학습 내용이라 원음 그대로 둔다. 소금·대금·해금도 `sampleMode`가 `"multi"`라
멀티샘플 조건만으로 거르면 함께 걸린다 — `isWesternInstrument()`로 명시적으로 좁힌다.

## 증상과 원인

비올라로 그리면 펜 소리 앞부분이 무음처럼 들리고, 첼로는 즉시 난다. 잘못 잘린
`viola_D4.mp3`를 트림하고(2026-07-29-mis-cut-sample-head-trim), 음별 게인 천장 문제를
고친(2026-07-29-live-preview-note-gain-clamp) 뒤에도 남았다.

남은 원인은 코드가 아니라 **녹음의 세기 프로필**이다. `curate-western-samples.py`는
비올라만 `piano`(여리게) 원본을 고른다(violin·cello는 `forte`). 여린 활은 활 잡음 뒤에
음정이 서서히 뜬다. RMS가 아니라 **기음(fundamental) 에너지**로 "음정이 들리기 시작하는
시점"을 재면(도구: Goertzel, 지속 수준 -6 dB 도달):

| 칸 | 비올라 | 첼로 | 차이 |
| --- | --- | --- | --- |
| 도 | 110 ms | 10 ms | 100 ms |
| 레 | 70 ms | 20 ms | 50 ms |
| 솔 | 230 ms | 60 ms | 170 ms |
| 도′ | 230 ms | 80 ms | 150 ms |
| 레′ | 230 ms | 60 ms | 170 ms |

학생이 실제로 짚는 기본 칸(도·레·솔)에서 첼로는 10~80 ms, 비올라는 70~230 ms.
**게인을 올려도 아직 뜨지 않은 음정은 커지지 않는다** — 그래서 음량 보정으로는 안 고쳐졌다.

## 비교

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| 안정 구간에서 시작 (채택) | 모든 악기·칸이 env 램프(35 ms) 안에 소리 남. 엔진이 이미 계산하는 `loopStart` 재사용, 코드 1곳 | 펜 소리에서 자연 어택이 빠짐(펜은 지속음 피드백이 목적이라 수용) | **채택** |
| 비올라 게인 추가 인상 | — | 측정 기반 보정 규칙 위반 + 없는 음정은 안 커짐 | 금지 |
| 비올라를 forte 로 재큐레이션 | 근본 해결 | 원본 아카이브(`선율-서양(philharmonia)/`)가 이 PC에 없음. 음색 철학 변경 | 원본 확보 시 검토 |
| 파일별 어택 스킵 오프셋 표 | 정밀 | 15칸×8악기 측정·유지보수 부담. loopStart 가 이미 같은 일을 함 | 미채택 |

## 적용 방향

- `js/audio-engine.js` `_createSampleLivePreview` —
  `multi && isWesternInstrument(plan.instrument) && sustain.loop && loopStart != null`
  이면 `source.start(start, loopStart)`. 국악기·루프 없는 짧은 샘플은 기존 그대로.

### 악기별 음정 온셋 실측 (기음 Goertzel, 지속 수준 -6 dB 도달, 15칸 중앙값)

| 악기 | 중앙값 | 최대 | 35ms 초과 칸 | 적용 |
| --- | --- | --- | --- | --- |
| cello | 180 ms | 300 ms | 12/15 | 적용 |
| viola | 160 ms | 390 ms | 15/15 | 적용 |
| flute | 150 ms | 160 ms | 15/15 | 적용 |
| doubleBass | 150 ms | 500 ms | 15/15 | 적용 |
| oboe | 120 ms | 130 ms | 15/15 | 적용 |
| frenchHorn / violin | 110 ms | 150·170 ms | 15/15 | 적용 |
| clarinet | 60 ms | 70 ms | 15/15 | 적용 |
| haegeum | 80 ms | 240 ms | 14/15 | **제외**(국악) |
| sogeum | 20 ms | 30 ms | 0/15 | **제외**(이미 빠름) |
| daegeum | 10 ms | 90 ms | 1/15 | **제외**(이미 빠름) |

서양 원본은 세기·주법과 무관하게 전부 느리다(활·입김이 실리는 시간). 국악 원본은 반대다.
- 안정 구간은 `continuousSustainPlan`이 굽는 크로스페이드 버퍼의 `loopStart`(기본 28% 지점,
  제로크로싱 정렬 완료)라 클릭 없이 시작한다. env 램프(35 ms)가 나머지를 부드럽게 만든다.
- 실측(출력 파형 재구성): 수정 전 비올라 솔 칸은 100 ms 시점에도 -39 dB(어택 대기),
  수정 후 모든 악기·칸이 20~50 ms 안에 지속 수준(-30 dB 안팎) 도달. 비올라·첼로 차이가
  50 ms 창에서 ~0.2 dB 로 줄었다.
- `test/audio-engine-live-stable-start.test.js` — loopStart 시작·짧은 샘플 폴백을 검증.
  **고치기 전 코드에서 실패하는 것을 확인했다.**

## 함께 알게 된 것

같은 증상("비올라만 펜이 늦다")의 원인이 세 겹이었다: ① `viola_D4.mp3` 앞 0.336초의
잘못 잘린 잡음(레 칸 한정, 가장 컸음) ② 음별 게인이 천장에 잘려 사라짐(비올라·프렌치호른)
③ piano 세기 녹음의 느린 음정 온셋(비올라 전 칸, 이 ADR). ①②를 고쳐 줄었지만
③이 남아 "여전히 늦다"로 들렸다. 증상이 하나라고 원인이 하나라는 보장이 없다.
