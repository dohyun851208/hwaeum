# 자연스러운 음 전환과 연주 표현 보존

2026-10-02 · [초기 지속음 구현](2026-10-02-sustain-source-calibration.md)의 후속 수정

## 결정

다른 음원 사이에는 40ms sin/cos 등전력 페이드를 적용한다. 펜은 새 칸에 70ms 머물 때 음을 바꾼다. 같은 칸의 수평 획은 소스 하나를 유지한다. 음량 보정은 느린 감쇠만 따라가도록 바꾸고, 전체 재생의 첫 어택과 해금의 음 사이 미끄러짐을 복원한다.

### 전환과 입력

- 라이브의 기존 선형 겹치기는 서로 다른 녹음의 중간에서 전력을 낮췄다. 새 발음은 sin, 나가는 발음은 cos 곡선을 16개 램프로 예약한다. 소스별 조율·음별 게인은 계속 해당 녹음에 고정한다. 최종 릴리스와 루프 내부의 상관 보정 페이드는 별도 정책이다.
- `liveDrawingMove`는 마지막 칸 변경 후 70ms에 한 번 전환한다. 같은 칸 안의 추가 이동은 타이머를 다시 시작하지 않는다. 펜이 멈춰도 새 음으로 넘어가며, 되돌아오기·펜 떼기·정지·악기 변경은 타이머와 늦은 로딩 응답을 취소한다. 첫 음에는 체류 지연을 넣지 않는다.
- `drawing.js`의 기존 110ms 미리듣기 제한은 작은 경계 왕복도 버려 체류 판정을 잘못 유지했다. **양자화된 칸이 바뀌면 즉시 엔진에 전달**하고 같은 칸 안에서만 기존 제한을 유지한다. 자유 그리기와 음악에 맞춰 그리기에 공통 적용한다.
- 레시피의 획을 70점으로 균등 축소하면 짧은 복귀가 탈락해 저장 재생에 긴 새 음이 생겼다. 선율 획은 음 경계 전후의 점과 원래 좌표 정밀도를 보존한다. 70점은 시각용 목표이며 경계가 많으면 초과를 허용한다. 파일/링크가 더 커질 수 있지만 레시피 형식은 그대로다. 썸네일용 평탄 경로의 기존 제한은 유지한다.
- 저장 획은 작품 시간에서 동일한 70ms 체류 규칙을 적용한다. 소리는 후보 음의 시작점보다 70ms 뒤 바뀌며 그동안 이전 음을 유지한다. 자유 그리기의 마우스 이동 속도는 작품 시간과 다르므로 실제 손의 체류 시간과 저장 획의 체류 시간이 같다는 보장은 하지 않는다. 화면·저장 좌표·음높이 축은 변경하지 않는다. 명시적인 음표의 짧은 리듬은 이 필터로 지우지 않는다.
- 미리듣기·재생에서 음이 바뀌는 지연은 의도된 70ms다. 파일 로딩이 늦으면 기존 소리를 계속 내다가 준비된 시점에 연결한다. 지연이 전혀 없는 전환과 떨림 제거를 동시에 보장한다고 표현하지 않는다.

### 비브라토와 어택

- 80ms RMS 평탄화는 자연스러운 3~8Hz 진폭 변화까지 줄였다. 400ms 이동 평균을 두 번 적용한 에너지 추세로 바꿨다. 긴 창의 낮은 주파수 추세만 보정하며, 안정 구간 평균 에너지와 스테레오 상대 위상·음량은 유지한다. 3~8Hz 진폭 변조 대조 신호의 보존율을 90~110% 범위로 검사한다. 실제 악기의 비브라토를 모두 특정 수치 이상 보존한다는 뜻은 아니다.
- **저장 획·전체 재생·내보내기의 첫 음은 원음 구간 시작에서 5ms 클릭 방지 페이드로 발음한다.** 새 획마다 활·숨의 어택이 다시 나온다. 이어지는 음만 안정 구간에서 연결한다.
- 서양 펜 소리의 첫 음은 기존 7월 ADR대로 안정 구간에서 빠르게 응답한다. 국악 첫 어택은 펜에서도 보존한다. 초기 지속음 구현에서 전체 재생까지 어택을 건너뛴 것은 회귀였으며 복원했다.

### 해금

- 해금의 원음 전환에도 직전의 실제 진행 중 음높이를 넘겨준다. 두 소스는 각각의 조율 보정을 적용해 같은 음높이 곡선을 겹쳐 낸다. 고정 파일을 전체 음역으로 늘이는 방식으로 돌아가지 않는다.
- 기존 `setTargetAtTime`의 시정수는 전체 재생 **0.12초**, 라이브 **0.09초**로 복원한다. 이것은 목표까지 도달하는 총시간이 아니다(한 시정수에서 약 63%). 새로운 인위적 시작 꾸밈음은 추가하지 않는다.
- Web Audio의 `playbackRate`는 128프레임마다 갱신된다. 곡선 시작을 그 경계에 맞추고, 탐색 시 경과 위치도 같은 배속으로 누적한다. 소스의 초기 `playbackRate.value`도 설정해 첫 렌더 블록에서 기본값 1로 시작하지 않게 한다. 연속 수학 적분만 사용하면 복원한 곡선은 맞아도 버퍼 위치가 틀어졌다.
- 명세: [setTargetAtTime의 시정수](https://www.w3.org/TR/webaudio-1.0/#dom-audioparam-settargetattime), [AudioBufferSourceNode의 playbackRate](https://www.w3.org/TR/webaudio-1.0/#dom-audiobuffersourcenode-playbackrate). 실제 Chrome 렌더로 별도 확인했다.

### 가야금과 조율 신뢰도

- 앞서 사용자가 선택한 자연 감쇠를 유지한다. 펜을 떼거나 획이 끝나도 분리된 원음의 여운은 남으며, 전체 정지는 즉시 종료한다. 원음의 다음 발음이 새어 나오지 않게 하는 길이 제한은 유지한다.
- 초기 ADR의 170칸 전수 정확도 주장을 정정했다. 같은 보정 분석기의 재측정과 독립 검증을 구분한다. 사용자 제공 외부 검토 기준은 161칸 확인·9칸 불확실이며 이를 새 독립 실측으로 재포장하지 않는다.
- 비올라 맨 아래 솔·위쪽 파는 `reviewRequired`로 표시한다. 확정 조율값으로 간주하지 않고 기존 후보값을 임시 유지한다. 보정을 끄면 더 정확하다는 근거도 없으며, 이번 진단에서 맨 아래 솔의 추정 중심값은 보정 없이 약 +26센트였다(동일 분석기 결과). `--write` 재측정은 이 두 후보값을 자동으로 덮어쓰지 않는다. 청감 비교 페이지에는 조율 보정을 끈 대조음도 제공한다.

## 비교와 검증

- Chrome 48kHz와 44.1kHz: 서로 직교하는 일정 음량의 대조음으로 전환 곡선 자체를 분리해 측정했다. 중간 6ms 창은 기존 **−2.98dB → 약 −0.01dB**. 실제 녹음의 음량·위상 차이가 모두 사라진다는 뜻은 아니다.
- 실제 바이올린 녹음, 2초 동안 40회 경계를 왕복한 저장 획: **41개 소스 → 1개**. 라이브에서도 41개 → 1개, 새 칸 유지 후 2개, 펜을 떼면 예약된 다음 발음 취소를 확인했다. 사용자 보고의 37개·4.6dB와는 입력/측정 창이 다르므로 같은 수치를 재현했다고 쓰지 않는다.
- 실제 캔버스의 자유/음악에 맞춰 그리기에서 작은 경계 왕복, 저장 획, 펜 떼기를 확인했다. 두 모드 모두 떨림 중 소스 하나를 유지한다.
- 바이올린·첼로 긴 음, 바이올린 전환/경계 떨림, 해금 선율, 비올라 두 음을 수정 전후 WAV로 렌더링했다. 바이올린 첫 음은 실제 MediaRecorder의 WebM/Opus로도 내보냈다. 재생 시작 위치는 안정 구간에서 원음의 시작으로 복원되며 브라우저 오류는 없다.
- 해금은 전환 중/전환 후 네 위치에서 탐색 렌더와 전체 렌더를 비교했다. 두 샘플레이트에서 파형 오차가 원래 신호의 한 샘플 변화량보다 작았다. 서로 다른 컨텍스트 간 PCM 완전 일치를 약속하지 않는다.
- 포락선 변경 후 루프 160칸에서 이음매 꺾임이 내부 최댓값을 넘는 사례는 0개였다. 화면 170칸의 매핑 불일치 0개, 수평 획 소스 수는 모두 1개였다. 악기별 평균 출력 재측정은 기존 기준에서 약 0.1dB 이내여서 측정된 게인 표와 ±3dB/더블베이스 ±12dB 한도를 유지한다.

## 재현과 적용

`npm test`, `node tools/smoke.cjs`로 회귀를 검사한다. 실제 브라우저 비교는 로컬 서버를 열고 아래 도구로 수행한다(Playwright·Chrome 별도 설치).

```powershell
node tools/verify-sustain-transitions.cjs output/sustain-review f5f31bc
node tools/measure-sustain.cjs output/sustain-review/measure-48000
npm run measure:loudness -- --notes
```

`PLAYWRIGHT_MODULE`·`CHROME_PATH`로 기존 설치 경로를 지정할 수 있고 `SAMPLE_RATE=44100`으로 다른 샘플레이트를 검사한다. 비교 페이지는 `output/sustain-review/index.html`, 오디오·진단 파일은 같은 폴더에 생성된다. 출력물은 git/배포에서 제외된다. 수치 검증과 청감 평가는 별개이며 사람의 청취 합격을 주장하지 않는다.

이번 수정은 `fix/melody-transition-naturalness` 브랜치에서 기존 배포 커밋 `f5f31bc` 다음 변경으로 분리했다. 이전 브랜치의 공유 이력은 재작성하지 않았다. 후속 PR은 `fix/preserve-melody-time`을 기준으로 비교하면 이번 수정만 검토할 수 있다. main 대상 전체 이력 정리는 별도의 병합 전략이며 이번에 기존 커밋을 임의로 제거하지 않는다.
