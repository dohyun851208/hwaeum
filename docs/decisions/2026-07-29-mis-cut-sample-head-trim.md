# 원본 테이크의 "그 음이 아닌 머리"는 큐레이션 단계에서 잘라낸다

확인일: 2026-07-29

## 결론

원본 필하모니아 테이크 중엔 **목표 음이 아닌 소리**(활 삑소리·옆 테이크 누출)가 먼저 들어간 뒤에야
진짜 음이 시작되는 것이 있다. 오디오 엔진은 멀티샘플을 항상 파일 맨 앞부터(`offset: 0`) 재생하므로
그 머리가 통째로 **재생 지연**으로 들린다.

이런 파일은 엔진에서 우회하지 않고 **큐레이션 단계에서 잘라낸다** —
`tools/curate-western-samples.py`의 `HEAD_TRIMS`에 등록하면 복사할 때 그만큼 트림해서 내보낸다.

첫 사례: `viola` 레 칸(midi 62, `viola_D4.mp3`) — 앞 **0.336초**를 잘라냄.

## 증상과 원인

3단계 선율 그리기에서 아래에서 5번째 **레** 칸을 비올라로 그리면 음이 한 박 늦게 나오고,
같은 칸을 첼로로 그리면 즉시 난다.

`viola_D4.mp3`(수정 전, 1.83초)의 실제 내용:

| 구간 | 내용 | 피치 |
| --- | --- | --- |
| 0.00 ~ 0.32초 | 정체불명의 희미한 삑 소리 | 1225 Hz = **D#6** (2옥타브 반 위) |
| 0.32 ~ 0.36초 | 무음 | — |
| 0.36초 ~ 끝 | 진짜 레 | 292 Hz = **D4** ✅ |

악기·음별 게인을 적용한 뒤 첼로 같은 칸(`cello_D3.mp3`)과 비교한 체감 음량:

| 시각 | 비올라(전) | 첼로 | 차이 |
| --- | --- | --- | --- |
| 60 ms | -36.5 dB | -31.3 dB | 5 dB |
| 140 ms | -43.4 dB | -31.1 dB | **12 dB** |
| 340 ms | -46.0 dB | -29.5 dB | **16.5 dB** |

**엔진 쪽엔 결함이 없다.** 두 악기 모두 `js/audio-engine.js`에서 같은 `ctx.currentTime + 0.005`에
예약되고, 멀티샘플은 `multi ? { offset: 0, ... }`로 파일 맨 앞부터 재생된다(라이브 미리듣기·전체 재생 공통).

### 왜 큐레이션 도구의 onset 게이트를 통과했나

```python
onset_end = max(0.08, min(0.45, duration * 0.24))   # viola_D4 → 0.439초
onset_db  = db_for_range(samples, sample_rate, 0.05, onset_end)
if onset_db < MIN_ONSET_DB:  failures.append("onset")   # -42.0 dB
```

검사 구간 0.05~0.439초가 **정확히 삑소리 구간**이고 그 삑소리가 약 -42 dB이라 문턱을 간신히 넘겼다.
이 게이트는 "앞부분에 **소리가 있는가**"만 보고 "**그 음이 맞는가**"는 보지 않는다 —
**잡음이 있었기 때문에 오히려 합격했다.** 그래서 `MIN_ONSET_DB` 문턱을 올려도 이 결함은 잡히지 않는다.

## 비교

| 방식 | 장점 | 단점 | 판단 |
| --- | --- | --- | --- |
| mp3 머리 트림 (채택) | 라이브 미리듣기·전체 재생·내보내기가 한 번에 고쳐짐. 코드 변경 0 | 도구 재실행 시 되살아남 → `HEAD_TRIMS`로 해결 | **채택** |
| 이웃 음 빌려쓰기 (`SAMPLE_OVERRIDES`) | 기존 패턴과 동일 | 반음 피치시프트라 음색이 달라짐. 멀쩡한 원본을 버림 | 미채택 |
| 도구에 피치 기반 어택 검사 추가 | 근본적, 재발 방지 | 원본 폴더가 있어야 재선정 가능 | 원본 확보 시 후속 |
| 엔진에서 온셋 자동 트림 | 일반 해법 | 모든 악기의 타이밍·음량에 영향. 결함 파일 1개에 과함 | 미채택 |

## 적용 방향

- **음원**: `sound/선율-서양(필하모니아)/현/viola/viola_D4.mp3` — 앞 0.336초 제거 후 모노 96k 재인코딩.
  1.83초 → 1.49초. 자른 뒤엔 0.02초부터 292.1 Hz(D4)가 나고 60 ms에 제 음량에 도달한다(첼로와 동급).
  자를 지점은 잡음과 진짜 음 사이 이음매(-65 dB, 336 ms)라 **진짜 활 어택은 보존된다.**
- **도구**: `tools/curate-western-samples.py`의 `HEAD_TRIMS[(inst_id, midi)]` →
  `copy_sample()`이 복사 대신 `trim_head()`로 내보낸다. 도구를 다시 돌려도 같은 파일이 재생성된다
  (검증: md5 일치).
- **안전장치**: `HEAD_TRIMS` 항목은 `srcToken`으로 **실측한 테이크를 고정**한다. 나중에 큐레이션이
  다른 테이크를 고르면 그 초 값은 의미가 없으므로 `handle_stale_head_trim()`이 실행을 멈추고
  사람에게 재확인을 요구한다 — 조용히 넘기면 잡음이 소리 없이 되살아나기 때문.
- **음량 보정은 갱신하지 않는다.** `npm run measure:loudness -- --notes`를 자르기 전후로 돌려
  비교한 결과 viola 62는 `1.413` 그대로, 악기 전체도 -23.81 → -23.83 dB(잡음 수준)로 동일했다.
  `findStableLoopRegion`이 내용 기반이라 트림과 무관하게 같은 지속 구간을 잡기 때문.

## 범위

도화지 15칸에서 닿는 서양 악기 음원 **117개를 전부 스캔**(머리 0.03~0.28초 vs 본체 0.5~1.2초 피치 대조)했다.
자동상관의 옥타브·배음 오검출(정확히 12.0 / 19.0 / 24.0 반음 차로 뜨는 것들)을 걷어내면
**진짜 결함은 `viola_D4.mp3` 하나뿐**이다. 새 음원을 넣을 때 같은 대조를 돌려 확인할 것.
