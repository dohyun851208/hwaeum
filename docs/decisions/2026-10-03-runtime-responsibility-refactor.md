# 런타임 책임 분리와 실제 출력 보존

## 결론

빌드 없는 classic script 구조와 기존 공개 API·레시피 형식을 유지하면서, 큰 모듈 안의 독립 책임을 팩토리 모듈로 분리한다. 실제 로드 순서는 `studio.html`·`channel.html` 한곳에서 관리하고, Node 검증 도구도 HTML의 순서를 읽는다.

시작 시 작업 폴더에 있던 화면·음원·조율 작업을 기준으로 삼는다. 비교 기준은 git HEAD가 아니라 작업 시작 시 소스 스냅샷이다. 음악 규칙, 측정 게인 표, 음원 파일, 화면 디자인은 이번 구조 변경의 대상이 아니다.

## 비교

| 선택 | 장점 | 한계 |
| --- | --- | --- |
| 기존 파일에서 함수만 재배치 | 로드 관계가 늘지 않음 | 저장·입력·렌더 책임이 계속 섞이고 독립 행동 검증이 어려움 |
| ES 모듈·번들러로 전환 | 정적 import와 묶음 관리 가능 | 실행 방식·배포 경계를 함께 바꾸며 프로젝트의 무빌드 제약과 충돌 |
| 의존성을 주입하는 classic-script 팩토리 | 현재 실행 방식을 유지하고 순수 변환·자원 수명을 따로 검증 가능 | HTML의 의존 순서를 검증해야 함 |

세 번째를 선택한다. 공통 함수를 무조건 범용 유틸로 모으지 않고, 샘플 가공·그림 렌더·레시피·감상 입력·로컬 저장이라는 실제 변경 단위에 맞춘다.

## 적용 방향

- `audio-samples.js`: 지속음 루프와 버퍼 가공·캐시를 맡는다. 가공 결과를 값으로 돌려주고, 실제 AudioBufferSourceNode의 버퍼 지정과 스케줄은 `audio-engine.js`가 맡는다. 측정 게인 상수는 엔진에 유지한다.
- `drawing-renderer.js`: 피치 축·색·가이드·획 렌더를 맡는다. 포인터, 좌표 저장, 실행 취소, 붓 커서는 `drawing.js`에 남긴다. 기존 DrawingCanvas 메서드와 정적 API를 유지한다.
- `studio-recipe.js`: 상태와 드로잉 스냅샷을 받아 직렬화·음 생성·사용 악기를 계산한다. DOM과 현재 화면 선택을 읽지 않는다. 저장 작품의 음 생성은 그 작품의 악기를 기준으로 한다.
- `studio-reflection.js`: 감상 메모 인계, 성찰 입력, 태그 UI를 맡는다. 불러온 작품의 성찰은 빈 문자열까지 보존하며 이전 작품의 메모로 덮어쓰지 않는다.
- `share-local-store.js`: IndexedDB와 객체 URL의 수명을 소유한다. 기존 DB 이름·버전·레코드 형식을 유지한다. 갤러리와 작품의 일괄 삭제는 한 트랜잭션으로 처리하고, 커밋 후 URL을 해제한다. 페이지가 BFCache에 보관될 때는 URL을 유지한다.
- `channel.js`: 사용하지 않는 드로잉 이미지 생성 경로를 제거하고, 마지막 갤러리 요청만 화면에 반영한다. 이전 요청의 늦은 성공·실패가 새 갤러리를 덮어쓰지 못한다.
- `api/share/_utils.cjs`: API 여섯 개의 동일한 오류 응답 처리를 공유한다. 상태 코드와 한국어 메시지는 유지한다.

`tools/runtime-scripts.cjs`는 HTML에서 스크립트를 읽는 Node 전용 로더다. 스모크·오디오 행동 테스트·음원 측정에서 중복 파일 목록을 제거한다. 새 모듈의 의존 관계는 `test/runtime-scripts.test.js`에서 검사한다.

검증은 단위 테스트 → jsdom 스모크 → 로컬 HTTP 서버의 실제 Chromium 순서로 수행한다. `tools/verify-runtime.cjs`는 임시 브라우저 프로필과 공유 API 대체 응답을 사용해 실제 IndexedDB·제작·내보내기·갤러리를 검사한다. 선택적 `REFACTOR_BASELINE_DIR`를 주면 같은 음원으로 13개 악기의 PCM 해시와 캔버스 픽셀 해시를 비교한다. 결과 파일은 gitignore된 `output/refactor-review/`에 둔다.

작업 범위와 검증 결과는 [구현 계획](../plans/2026-10-03-runtime-refactor.md)에 기록한다. 서버 API의 실제 Vercel Blob 저장은 별도 배포 환경 검증 범위다.
