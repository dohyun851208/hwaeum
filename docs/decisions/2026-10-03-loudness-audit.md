# 악기·음별 음량 전수 점검 — 측정 오차 2개, 펜 소리 상한, 튀는 녹음 교체, 국악 음별 한도

확인일: 2026-10-03 · 선행: [악기별/음별 선율 음량 보정](2026-06-28-instrument-loudness-calibration.md),
[펜 소리 음별 보정 상한](2026-07-29-live-preview-note-gain-clamp.md), [고르지 않은 녹음 교체](2026-10-03-steady-sustain-takes.md)

## 결론

"특정 음이나 악기가 지나치게 작은지" 점검했다. 13개 악기 170칸을 앱 엔진 그대로(크롬 오프라인 렌더) 재생해 쟀다.
작게 들리는 원인은 네 가지였고, 셋은 고쳤고 하나는 규칙을 바꾸지 않는 범위에서 녹음 선택으로 풀었다.

1. **측정 도구가 스테레오 단소를 3.0 dB 크게 쟀다.** `ffmpeg -ac 1`의 float 모노 다운믹스는 두 채널을 √½씩 더한다.
   단소 녹음(`단소.mp3`)만 두 채널이 같은 스테레오(상관 1.000)라 3 dB가 부풀었고, 단소 게인이 그만큼 낮게 잡혔다.
   → 도구가 원래 채널 그대로 디코드해 채널 평균 전력으로 잰다(엔진처럼 첫 채널로 구간을 찾고 모든 채널을 굽는다).
2. **국악 음색 필터를 측정에 반영하지 않았다.** 재생은 국악기(가야금 제외)에 저역 통과 2300 Hz·Q 0.9(Web Audio 기준 dB)를
   거는데, 공진 때문에 해금 +1.7, 단소 +0.8, 소금 +0.6, 대금 +0.2 dB 커진다. → 도구도 같은 필터를 거쳐 잰다.
3. **펜 소리 기준 게인 상한 0.95가 악기 게인이 큰 악기를 잘랐다.** 플루트·비올라·호른·클라리넷의 펜 소리가 재생보다
   0.3~1.8 dB 작아 악기끼리 크기가 어긋났다. 07-29 ADR이 "기준 게인 상한을 올리는 안"을 미채택한 이유는
   "펜 소리가 전체적으로 커진다"였는데, 이번 측정으로 그 상한이 오히려 펜 소리와 재생을 어긋나게 한다는 것이 확인돼 바꾼다.
   → 실제 녹음은 기준 3.2·최종 4.5, 합성음(음원 없이 열었을 때)은 예전 0.95·2.2를 그대로 쓴다.
4. **원음이 유난히 큰 칸 하나가 악기 전체를 작게 만들었다.** 악기 크기는 15칸 원음의 에너지 평균이라 큰 칸에 끌려간다.
   음별 보정은 ±3 dB라 그 칸을 다 줄이지 못하고, 그만큼 악기 게인이 내려가 나머지 칸이 작아진다
   (플루트 맨 위 솔은 중앙값보다 15.5 dB 커서 플루트 보통 음이 바이올린보다 2.6 dB 작았다).
   06-28 ADR 규칙("한도를 넘어야 괜찮은 샘플은 원본 선택을 다시 검토")대로 한도는 그대로 두고 서양 4악기 17칸의 녹음을 다시 골랐다.

| 악기 | 보통 음(바이올린 대비, K-가중) 전 → 후 | 칸 사이 차이 전 → 후 |
| --- | --- | --- |
| 플루트 | −2.6 → +0.2 dB | 14.2 → 2.0 dB |
| 호른 | −0.5 → −0.7 dB | 7.9 → 3.1 dB |
| 첼로 | −0.9 → −0.7 dB | 5.8 → 1.7 dB |
| 더블베이스 | −1.7 → −1.8 dB | 3.6 → 2.8 dB |
| 단소 | −2.0 → −0.1 dB | 5.3 → 1.6 dB |
| 해금 | +4.0 → +1.6 dB | 6.7 → 1.0 dB |
| 대금 | +0.2 → −0.9 dB | 4.7 → 0.6 dB |
| 소금 | −3.7 → +0.2 dB | 17.3 → 3.8 dB |

국악 4악기는 사용자 확인 뒤 음별 보정 한도를 ±12 dB로 넓힌 결과다(아래 "국악기 낮은 음").

펜 소리는 모든 서양 악기에서 재생과 같은 크기가 됐다(바이올린 대비 펜 소리: 플루트 −4.4 → +0.2, 비올라 −2.4 → −0.9,
호른 −1.6 → −0.7, 클라리넷 −0.4 → −0.1 dB).
소금은 측정을 바로잡자 한때 1.2 dB 작아졌다. 맨 위 레·미가 필터로 더 커져 에너지 평균을 끌어올렸기 때문이다.
국악 음별 한도를 넓혀(아래) 해결했다. 이제 바이올린 보통 음보다 3 dB 넘게 작은 칸은 더블베이스 맨 아래 시·도뿐인데,
둘 다 실제 크기(RMS)는 −0.1 dB이고 아주 낮은 음이라 귀 기준(K-가중)으로만 작다.

## 측정 방법

- 각 칸을 4.5초 길게 그은 레시피를 앱 엔진(`schedule`, 마스터 0.56 + −3 dBFS 리미터)으로 48 kHz 렌더했다.
  펜 소리는 `_createSampleLivePreview`를 오프라인 컨텍스트에 붙여 같은 길이로 렌더했다.
- 0.3~4.4초 구간의 RMS, K-가중(ITU-R BS.1770) 크기, 노트북 스피커 근사(150 Hz 2차 고역 통과 ×2 + K-가중)를 쟀다.
  가야금은 뜯는 소리라 첫 0.25초로 잰다.
- 서양 8악기는 모든 칸에서 "도구 예측 − 3.35 dB = 실제 재생"(±0.1 dB)이라 도구 모델이 정확했다.
  국악기만 어긋났다(단소 −2.4, 해금 +1.6, 소금 +0.6, 대금 +0.2 dB) → 원인 1·2.
- 녹음 후보는 칸마다 같은 음·반음 옆의 모든 세기·길이 테이크(438개)를 받아, 도구와 같은 방식의 원음 크기와
  반복 길이·약해짐·음정을 쟀다. 그다음 크롬 재생 출렁임을 비교했다. 고르는 조합은 도구의 수렴 계산을 그대로 시뮬레이션해 정했다.

## 교체한 녹음

크기는 실제 재생 RMS, 기준(바이올린 미 −25.2 dB) 대비. 출렁임은 50 ms 크기의 상·하위 5% 폭.

| 칸 | 바꾼 녹음 | 크기 전 → 후 | 출렁임 전 → 후 |
| --- | --- | --- | --- |
| 플루트 맨 위 솔 | 솔#(G#6 pianissimo) 빌려 반음 내림 | +6.4 → −0.2 | 2.2 → 2.3 |
| 플루트 위쪽 파 | 미(E6 long piano) 빌려 반음 올림 | +3.9 → −0.3 | 3.6 → 0.8 |
| 플루트 위쪽 미 | 같은 음 long piano | +0.7 → −0.3 | 2.8 → 1.1 |
| 플루트 위쪽 도 | 도#(C#6 piano) 빌려 반음 내림 | −5.2 → −0.4 | 5.8 → 2.8 |
| 플루트 아래쪽 도 | 같은 음 forte | −5.9 → −0.2 | 3.3 → 1.5 |
| 플루트 아래쪽 시·라·솔 | 같은 음 mezzo-piano | −3.0~−4.3 → −0.2 | 3.2~5.9 → 1.7~2.2 |
| 호른 맨 위 솔 | 같은 음 piano | +3.7 → +0.9 | 0.5 → 0.5 |
| 호른 위쪽 레 | 레#(D#4 piano) 빌려 반음 내림 | −3.2 → 0.0 | 0.6 → 0.3 |
| 호른 위쪽 도 | 도#(C#4 mezzo-forte, 기존 파일) 빌려 반음 내림 | −4.2 → −2.2 | 0.9 → 1.1 |
| 호른 맨 아래 솔 | 같은 음 long forte | −3.8 → 0.0 | 0.5 → 0.3 |
| 첼로 맨 위 솔 | 파#(F#4 fortissimo) 빌려 반음 올림 | −4.3 → −0.2 | 3.9 → 1.1 |
| 첼로 아래쪽 파 | 같은 음 piano(10-02의 fortissimo 대신) | +2.8 → +0.5 | 2.5 → 1.6 |
| 첼로 맨 아래 솔 | 파#(F#2 forte, 기존 파일) 빌려 반음 올림(10-02의 G2 fortissimo 대신) | +2.6 → −0.1 | 0.8 → 1.1 |
| 더블베이스 위쪽 미 | 같은 음 forte | −2.2 → −0.2 | 2.1 → 2.1 |
| 더블베이스 위쪽 시 | 같은 음 1초 mezzo-forte | −3.0 → −0.2 | 2.5 → 3.1 |

첼로 맨 아래 솔·파의 fortissimo(10-02·10-03 ADR)는 고르지만 원음이 중앙값보다 8.7~8.8 dB 커서 첼로 게인을 끌어내렸다.
맨 아래 솔은 10-02 ADR의 대안(F#2 forte 빌리기)으로 바꿨고, 출렁임은 거의 같다.

## 적용 방향

- `tools/measure-instrument-loudness.cjs`: 원래 채널로 디코드(`decodePcm`이 채널 배열을 돌려줌), 첫 채널로 구간 검출,
  채널 평균 전력. 국악기(`GUGAK_TONE_FILTER_IDS`)는 엔진의 `configureSampleToneFilter`와 같은 저역 통과를 거쳐 잰다.
  둘 다 엔진 쪽을 바꾸면 함께 맞춘다. 서양 악기 결과는 바뀌지 않는다(모노·필터 없음).
- `js/audio-engine.js`: `LIVE_PREVIEW_MAX_GAIN` 3.2, `LIVE_PREVIEW_NOTE_MAX_GAIN` 4.5(플루트 · "그림소리 강조"에서 기준 3.11·최종 4.40),
  합성음은 `SYNTH_LIVE_PREVIEW_MAX_GAIN` 0.95·`SYNTH_LIVE_PREVIEW_NOTE_MAX_GAIN` 2.2. 상한을 올려도 "그림소리 강조"에서
  서양 악기 펜 소리 피크는 최대 −12.6 dBFS(비올라, 플루트 −15.9)다. 게인이 큰 악기일수록 원음이 작기 때문이다.
- 게인: 플루트 1.38 → 2.78, 호른 1.29 → 1.37, 첼로 0.75 → 0.90, 단소 0.21 → 0.27, 해금 0.45 → 0.37,
  소금 0.65 → 0.57, 대금 1.21 → 1.18. 음별 표는 도구 출력 그대로다.
- `tools/curate-western-samples.py`: 빌리기 7칸(`SAMPLE_OVERRIDES`)과 고정 테이크 13개(`TAKE_OVERRIDES`)를 더하고,
  첼로 G2 fortissimo 고정은 F#2 빌리기로, 첼로 F3 고정은 fortissimo에서 piano로 바꿨다. 조율(`sample-calibration.js`)은 `--write`로 다시 만들었다
  (바꾸지 않은 126개 파일은 최대 3.2센트 이동).
- 테스트: 펜 소리 기준 게인이 모든 서양 악기·모든 버전에서 악기 게인에 비례하는지 검사를 추가했다(0.95에서는 실패).
  악기 게인·빌린 칸 음정·게인 고정값을 새 값으로 바꿨다.

## 국악기 낮은 음 — 음별 보정 한도 ±12 dB (사용자 확인 후 적용)

- 소금 낮은 솔·라·도(−10.9 dB)·레(−9.6)·미(−5.5), 대금 도(−3.5), 단소 낮은 솔·라(−3.3), 해금 도(−4.8)가
  ±3 dB 한도에서 기준보다 작았다(실제 재생 RMS). 국립국악원 녹음은 음계를 한 번씩만 불어 대체 녹음이 없다.
  소금은 녹음 안의 음 사이 차이가 20.7 dB이고, 그 녹음이 낼 수 있는 가장 낮은 시를 4반음까지 내려 쓴다.
- "지금 ↔ 넓히면" 비교 소리를 들은 사용자가 적용을 확인했다. 국악 4악기(소금·대금·단소·해금)에도 더블베이스와 같은
  ±12 dB 예외를 준다(`WIDE_NOTE_GAIN_LIMIT_IDS` · 도구 `EXTENDED_NOTE_GAIN_IDS`, 루트 `CLAUDE.md`·`AGENTS.md` 규칙 갱신).
  악기 게인은 그대로이고 음별 표만 바뀐다. 보정 후 칸 사이 차이(도구): 소금 15.8 → 2.3, 대금 4.2 → 0.0, 단소 3.6 → 0.0, 해금 6.4 → 0.0 dB.
  소금 낮은 솔·라·도는 +12 dB에 닿아 기준보다 1.9 dB 작게 남는다(재생 RMS).
- 소금 녹음의 음 사이 잡음은 −105 dB라 10 dB를 키워도 잡음이 문제 되지 않는다.
- 대금 음별 값은 메인 `index.html`의 `TAKES`에도 복사돼 있어 같은 값으로 바꿨다.
- 소금 낮은 솔(uiMidi 55)이 +3 dB를 넘어 측정값대로 보정되는지 확인하는 테스트를 더했다(한도를 되돌리면 실패).

## 남은 문제
- **고르지 않은데 더 나은 녹음이 없는 칸**: 플루트 레(출렁임 6.5 dB), 첼로 위쪽 레(7.8)·솔(5.6), 더블베이스 미(6.9),
  바이올린 솔·라·레(6.1~6.7). 크기는 맞다.
- **참고(손대지 않음)**: 재생 경로의 리미터(`DynamicsCompressor`)는 자동 보정 이득으로 모든 소리를 약 1.7 dB 키운다.
  펜 소리에는 리미터가 없어 모든 악기에서 펜 소리가 재생보다 그만큼 작다(악기 간 균형과는 무관).
  더블베이스 낮은 음은 저음이 약한 노트북 스피커에서 8 dB 넘게 작게 들린다(맨 아래 시는 −18 dB). 녹음 크기가 아니라 스피커의 한계다.
  해금은 RMS로 맞춰도 밝은 음색 때문에 귀 기준(K-가중)으로 2.5 dB 크다. 측정을 K-가중으로 바꿀지는 별도 결정이다.
