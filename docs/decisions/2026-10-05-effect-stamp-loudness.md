# 효과음 도장 크기: 배경·선율과 다시 맞추고, 도장끼리는 새소리 기준 + 이름의 세기로

확인일: 2026-10-05 · 선행: [자연 효과음을 이름에 맞게](2026-10-02-nature-effect-sound-match.md), [귀 기준(A-가중) 악기 크기](2026-10-03-perceived-loudness-a-weighting.md)

## 결론

사용자가 처음에 "효과음이 악기·배경 소리보다 너무 작다, 원래 이 정도로 차이 나지 않았다"고 했다.
고친 뒤 들어 보고 "효과음끼리도 차이가 크다. 빗소리는 잘 들리지도 않으니 새소리 정도로 맞춰 달라"고 했고,
다시 들어 보고 "흑동고래·번개가 작고 폭풍우는 빗소리 같고 바람도 작다"고 했다. 네 가지를 바꿨다.

1. **배경·선율 대비 크기**: `EFFECT_GAIN` 0.15 → 0.45. 재생 크기가 미리듣기와 같아진다.
2. **도장끼리의 크기**: manifest `effects[].gain`으로 새소리를 기준 삼아 맞추고, 이름의 세기만큼 더하고 뺀다(번개 +6 … 가랑비·먼 천둥 −3 dB).
3. **재생 중 페이드**: 찍은 순간부터 끝까지 직선으로 줄이던 것을, 끝 0.3초에서만 줄인다(`EFFECT_END_FADE_SECONDS`).
4. **녹음 교체**: 노트북 스피커에서 작게 들리던 바람 셋·번개·폭풍우·흑동고래를 픽사베이 녹음으로 바꿨다(아래 4절).

## 1. 배경·선율보다 9.5 dB 묻혔다

| 시점 | 배경(균형) | 선율(균형) | 효과음 도장 |
| --- | --- | --- | --- |
| 2026-06-26 도장을 넣었을 때 | `padGain` 0.17 | `melodyGain` 0.84 | `EFFECT_GAIN` 0.15 |
| 2026-06-27 "배경·선율 ×2" | 0.34 | 1.68 | 0.15 (그대로) |
| 이후 `BACKGROUND_OUTPUT_GAIN`·`WESTERN_MELODY_OUTPUT_GAIN` ×1.5 | 0.51 | 2.52 × 악기 보정 | 0.15 (그대로) |

배경·선율만 두 번 커지면서 효과음이 배경보다 9.5 dB(약 3배) 더 작아졌다. 처음엔 배경과 거의 같았다(−1.1 dB).
미리듣기와 재생도 어긋났다. 미리듣기(0.24)는 마스터를 거치지 않는데, 전체 재생은 마스터 0.56을 지나서 0.15 × 0.56 = 0.084였다.
고를 때보다 재생할 때 9.1 dB 작게 들렸다.
→ 배경과 같은 ×3(0.45)으로 올렸다. 마스터를 지나면 0.252라서 미리듣기와 0.4 dB 안쪽이다.
미리듣기는 `EFFECT_PREVIEW_GAIN` 0.24, 디코드를 기다리는 동안의 합성음은 `EFFECT_FALLBACK_PREVIEW_GAIN` 0.135로 떼어 그대로 둔다.

## 2. 도장끼리 24 dB 차이

파일 크기가 새 −14.2부터 가랑비 −38.3 LUFS까지 24 dB 벌어져 있었다. 10-02 결정은 "이름의 세기"대로 파일 목표를 −18~−27 LUFS로 정했다.
하지만 가랑비·소나기·동물·효과 도장은 원본 그대로였고, 그 범위도 배경 위에서는 너무 넓었다.

- 파일을 다시 만들지 않고 manifest `gain`으로 맞춘다. 픽사베이 원본이 이 PC에 없어서 다시 만들면 MP3를 두 번 인코딩해야 한다.
  또 빗방울·가랑비는 피크가 평균보다 27 dB 높아서 파일 안에서 키우면 리미터가 '똑' 소리 머리를 깎는다.
  게인은 엔진의 부동소수 경로에서 곱하므로 이 제약이 없다.
- `tools/measure-effect-loudness.cjs`가 파일마다 통합 크기(EBU R128)를 재서 새소리에 맞는 gain을 추천한다.
  미리듣기는 리미터를 거치지 않으므로, 키운 뒤 피크가 −1 dBFS를 넘지 않게 묶는다(큰 빗방울만 0.9 dB 덜 키움).
  `--check`는 manifest 값이 추천값과 0.5 dB 넘게 다르면 실패한다.
- 모든 도장 파일은 모노다. 스테레오 파일이면 같은 숫자라도 3 dB 다르게 들린다.
- 빗소리 에너지는 150 Hz 위에 있다(아래 대역이 11~16 dB 작다). 가랑비를 21 dB 키워도 웅웅거림이 커지지 않는다.

## 3. 끝까지 직선으로 줄이던 페이드

전체 재생은 찍은 순간부터 파일 끝까지 0으로 줄였다(첫 버전부터 있던 동작). 7.8초 산들바람은 3.9초에 이미 −6 dB였고,
이어지는 소리는 평균 4.8 dB를 잃었다. 파일에는 `build-nature-effects.py`가 넣은 페이드아웃이 이미 있어서 두 번 줄어들었다.
그대로 두고 도장끼리 맞추면 긴 소리의 첫머리가 새보다 커진다. 그래서 끝 0.3초(0.3초보다 짧은 소리는 마지막 4분의 1)에서만 줄인다.
작품 끝에 잘리는 도장도 같은 방식으로 끝에서 줄어들어 딱 끊기지 않는다.
이제 "파일 크기 × gain = 앱 속 크기"가 성립해서, 도구가 파일만 재도 앱 속 크기를 맞출 수 있다.

## 측정 (1~3을 고친 직후, 앱 엔진 `renderOffline`, 크롬 렌더, 스테레오 통합 LUFS)

참고: 밝은 배경 −22.0, 바이올린 선율 −22.0, 대금 선율 −20.0, 숲 소리풍경 −34.6.

| 도장 | 전 | 후 |
| --- | --- | --- |
| 새 · 벨 · 번개 · 뻐꾸기 | −35.4 · −33.9 · −35.9 · −36.1 | −21.6 · −21.4 · −21.5 · −21.8 |
| 흔들리는 잎 · 소나기 · 큰 빗방울 | −45.2 · −46.2 · −48.1 | −21.4 · −21.6 · −22.5 |
| 산들바람 · 가랑비 · 먼 천둥(3 dB 작게) | −47.2 · −59.2 · −44.9 | −24.4 · −24.4 · −24.5 |

20개 도장이 −33.9~−59.2(25 dB 폭)에서 −21.4~−22.5(1.1 dB 폭)로 모였다. 이름이 약한 셋은 그보다 3 dB 아래다.
도장 7개를 찍은 30초 합주의 피크는 −4.9 dBFS다. 일부러 가장 시끄럽게 겹친 경우도 쟀다.
"활기찬" 배경을 공간 강조로 깔고 큰 소리 도장 10개를 6초 안에 찍었더니, 146만 샘플 중 8개가 0 dBFS를 0.35 dB 넘었다.
리미터 반응 시간(3 ms) 안에 새는 순간 피크라 들리지 않는다. 그래서 리미터는 그대로 둔다.
비교 청취 페이지: `output/effect-balance-review/`(git·배포 제외).

## 4. 들어 보고 바꾼 녹음과 이름의 세기 (같은 날, 두 번째 청취)

맞춘 뒤 사용자가 들어 보고 "상당히 좋아졌다. 그런데 흑동고래·번개가 너무 작고, 폭풍우는 그냥 빗소리 같고,
바람도 전반적으로 작다. 너무 작은 건 픽사베이 같은 데서 새것으로 바꾸고 키워도 된다"고 했다.

- **크기 숫자는 맞았는데 작게 들린 이유**: 지금 녹음들은 소리가 배경음악과 같은 중간 대역(250 Hz~2 kHz)이나
  200 Hz 아래에 몰려 있었다(거센바람은 노트북 대역에서 3.4 dB, 폭풍우 4.6 dB가 사라짐. 폭풍우의 천둥은 거의 저음뿐이라 빗소리만 남았다).
  흑동고래는 소리가 모두 중간 대역이고 앞 1.2초가 4.3 dB 작았다. 간단한 가려짐 모델도 만들어 봤지만 번개·소나기를 새보다 2배 크다고 내놓는 등
  귀와 맞지 않아 버렸다. 크기는 사용자의 귀를 기준으로 정한다.
- **녹음 교체**: 픽사베이에서 후보 72개를 받아(자동 다운로드가 막혀 브라우저로 목록을 모으고 CDN에서 받음) 노트북 대역 비율·앞 1초의 천둥/울음·
  잡음을 쟀다. 자리마다 2~3개를 같은 크기로 맞춰 비교 페이지(`output/effect-replace-review/`)를 만들었고,
  사용자가 고르지 않고 "계속"이라고 해서 측정이 가장 나은 것으로 정했다(다른 후보로 바꿔 달라고 하면 표만 고친다).

| 도장 | 바꾼 녹음(픽사베이) | 고른 이유 |
| --- | --- | --- |
| 산들바람 | Wind Blowing SFX 10 (DRAGON-STUDIO) 7.1~15.1초 | 살랑 커졌다 작아지고 1~4 kHz가 55% |
| 거센바람 | Wind Blowing (SoundReality) 19.6~26.6초 | 쏴아 세게 이어짐, 노트북 손실 1.5 dB |
| 회오리바람 | Strong Howling Wind (Liecio) 74.0~81.9초 | 휘이잉 휘파람이 오르내림(2 kHz 위 −12~−2 dB) |
| 폭풍우 | Thunderstorm (bijan6207) 40.9~49.9초 | 0.3·4.8초에 천둥 + 고음까지 끊기지 않는 굵은 비 |
| 번개 | Lightning Strike (freesound_community) 1.8~9.3초 | 첫 순간 2 kHz 위 '쩍', 노트북 손실 0.4 dB |
| 흑동고래 | Whale (freesound_community) 0.9~5.9초 | 울음이 1~4 kHz까지 올라감(24%) — 배경에 덜 묻힘 |

  다듬기는 `build-nature-effects.py` 표에 적었다(리미터는 모두 2.3 dB 안쪽). 흑동고래는 동물 도장 자리(`효과음-도장/동물/흑동고래.mp3`)를 그대로 쓴다.
  쓰지 않게 된 유자레코즈 다듬은 파일 5개는 지웠고, 유자레코즈 원본(바람1~3·천둥2·3)은 저장소에 남긴다. 출처는 픽사베이 `라이센스.txt`.
- **이름의 세기**: `measure-effect-loudness.cjs`의 `LEVEL_DB`로 새보다 번개 +6, 폭풍우·거센바람 +4, 회오리바람·흑동고래 +3 dB.
  산들바람의 −3 dB는 없앴고, 가랑비·먼 천둥만 −3 dB다.
- **확인**(앱 엔진 크롬 렌더, 스테레오 LUFS): 새 −21.6, 산들바람 −21.5, 회오리바람 −18.5, 흑동고래 −18.4, 거센바람 −17.5, 폭풍우 −17.5, 번개 −15.5.
  미리듣기 피크 한도에 걸린 소리는 없다. 가장 시끄러운 배경("활기찬" 공간 강조 + 첼로)에 여섯 개를 다 찍어도 피크 −0.2 dBFS.
  들어 볼 페이지: `output/effect-final-review/`.

## 5. 들어 보고 다시 줄임 (2026-10-12)

사용자가 앱에서 들어 보고 배경음악은 10%, 효과음은 20% 줄여 달라고 했고, 다시 들어 보고 효과음을 10%씩 두 번 더 줄여 달라고 했다.

- 효과음 세 값을 같은 비율(× 0.8 × 0.9 × 0.9 = × 0.648, 약 −3.8 dB)로 줄였다. `EFFECT_GAIN` 0.45 → 0.2916, `EFFECT_PREVIEW_GAIN` 0.24 → 0.15552,
  `EFFECT_FALLBACK_PREVIEW_GAIN` 0.135 → 0.08748. 재생(× 마스터 0.56 = 0.163)과 미리듣기의 차이는 그대로 0.4 dB다.
- 배경은 `BACKGROUND_OUTPUT_GAIN` 1.5 → 1.35. 배경 구간 플레이어(`bgPlayer.volume`)와 2단계 미리듣기(`bgPreview.volume`)도 같은 × 0.9.
- 미리듣기가 작아져 피크 여유가 생기자 큰 빗방울이 더는 피크 한도에 걸리지 않아, 도구 추천대로 `gain` 4.29 → 4.73(새소리 기준 목표 크기).
- 그 결과 효과음 게인이 균형 배경보다 −3.9 dB가 됐다. 사용자가 귀로 정한 크기라서 아래 경보선을 −3에서 −4 dB로 옮겼다.
  경보는 여전히 처음 문제(−9.5 dB)처럼 배경만 키우고 효과음을 잊은 경우를 잡는다.

## 지킬 것

- 효과음 파일을 바꾸거나 `build-nature-effects.py`로 다시 만들면 `node tools/measure-effect-loudness.cjs`로 재서 manifest `gain`을 고친다.
  크기를 귀로 다시 정할 땐 그 도구의 `LEVEL_DB`(새보다 몇 dB)만 고친다.
  `target_lufs`는 이제 인코딩·리미터 여유를 위한 값이고, 앱 속 크기는 `gain`이 정한다.
- 숫자로 같은 크기여도 소리가 배경음악과 같은 대역에 몰리거나 노트북이 못 내는 저음뿐이면 작게 들린다. 녹음을 고를 땐 노트북 대역(150 Hz 위)에 소리가 있는지 본다.
- `test/audio-balance.test.js`가 두 가지를 지킨다. 재생 중 효과음(× 마스터)이 미리듣기와 ±1 dB 안쪽인지, 효과음 게인이 균형 배경보다 4 dB 넘게 작지 않은지 본다(2026-10-12에 3 → 4 dB, 5절).
  배경·선율 게인을 키울 때 효과음도 함께 보라는 경보다.
- `test/manifest-contract.test.js`는 모든 도장에 gain이 있고 새소리가 1(기준)인지 본다.
