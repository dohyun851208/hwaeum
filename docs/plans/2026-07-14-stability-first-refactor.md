# 안정성 중심 1차 리팩터링

작성일: 2026-07-14

## 목표

큰 파일을 한 번에 나누지 않고, 실제 오류가 확인된 경계부터 테스트 가능한 책임으로 정리한다. 사용자 동작과 저장 형식은 유지하되 잘못된 끝점 처리와 데이터 손실은 바로잡는다.

## 현재 확인된 문제

- `audio-engine.js`의 WebM 저장 결과가 함수 범위 밖 `mimeType`을 읽어 저장 클릭 뒤 `ReferenceError`를 낸다.
- `drawing.js`의 지우개가 길이 1인 획과 분할 조각을 무조건 버려, 지우개에서 먼 한 점 선율도 사라질 수 있다.
- `music-core.js`의 선율·리듬 샘플 위치와 실제 재생 시간이 서로 다른 격자를 사용한다. 빈 리듬 경로는 예외를 내고 곡 끝의 리듬 칸은 누락될 수 있다.
- `studio.js`의 `renderComposeInstruments()`와 `studio-setup-render.js`의 `selectInstrument()`가 서로를 호출해 설정 렌더 경계가 양방향으로 결합돼 있다.

## 작업 순서

1. 각 결함의 회귀 테스트를 먼저 추가한다.
   - WebM 저장 결과는 실제 Blob의 MIME 형식을 반환하고 임시 링크를 정리한다.
   - 먼 단일점은 지우개에서 보존하고, 가까운 단일점만 삭제하며 Undo로 복원한다.
   - 빈 리듬 입력, 마지막 유효 격자, 곡 끝의 탭 음표를 경계 테스트로 고정한다.
2. 드로잉 지우개에서 “획을 지우개 밖 조각으로 나누는 계산”을 별도 순수 헬퍼로 분리한다.
3. 음악 코어에서 실제 초 단위 격자를 만드는 공통 샘플러를 사용해 선율과 리듬의 좌표계를 통일한다.
4. WebM 저장 결과의 MIME 형식을 생성된 Blob에서 읽도록 수정한다.
5. `renderComposeInstruments()`의 구현을 설정 렌더 모듈로 옮기고, `studio.js`에는 기존 호출부를 위한 얇은 래퍼만 둔다. 양방향 콜백과 외부에 노출할 필요가 없는 반환 함수를 줄인다.
6. 단위 테스트, 통합 스모크, 로컬 서버 브라우저 확인을 차례로 수행한다.

## 완료 기준

- 기존 레시피 구조와 `window.SoundDrawing` 공개 API가 바뀌지 않는다.
- 단일점 획은 실제 지우개 반경 안에 있을 때만 사라진다.
- 생성된 모든 선율 음표가 곡 길이 안에서 끝나고, 리듬 온셋은 `0 <= time < duration`을 만족한다.
- WebM 저장 함수가 `{ size, mimeType }`을 오류 없이 반환한다.
- 악기 선택 시 2단계 카드, 3단계 작곡 악기, 음높이 축과 범례가 이전과 같이 함께 갱신된다.
- `npm test`가 모두 통과하고 로컬 브라우저 콘솔에 새 오류가 없다.
