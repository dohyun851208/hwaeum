# 아키텍처 후속 리팩터링

작성일: 2026-07-14

## 목표

안정성 중심 1차 리팩터링에서 의도적으로 미룬 코어·오디오·스튜디오 책임을 테스트 가능한 경계로 정리한다. 사용자 재생 흐름, 레시피 형식, 공유 방식과 `window.SoundDrawing` 공개 API는 유지한다.

## 호환성 원칙

- 저장 좌표와 레시피 스키마는 바꾸지 않는다.
- `window.SoundDrawing`의 기존 키와 `getStateSummary()`의 기존 필드는 제거하지 않는다.
- `MusicCore`의 기존 공개 함수는 앱 내부 호출이 없더라도 이번 단계에서는 호환 래퍼로 유지한다.
- 오디오 엔진의 transport 상태 머신은 `AudioEngine`에 남기고, 순수 계획 계산과 노드 소유권만 분리한다.
- 실제 화면에서 도달할 수 없는 스튜디오 내부 공유 목록·뷰어 DOM만 제거한다. 갤러리 생성, 작품 게시, `channel.html` 감상 흐름은 유지한다.
- 각 단계는 독립 테스트를 통과한 뒤 다음 단계로 진행한다. 회귀가 생기면 해당 단계 범위에서 원인을 해결하고 경계를 더 넓히지 않는다.

## 작업 순서

### 1. 공개 계약과 데이터 계약 잠금

- `window.SoundDrawing` 공개 키와 상태 요약 필드를 스냅샷 테스트로 고정한다.
- 악기·선율·분위기·배경·스타일 manifest의 ID 집합, 참조, 국악 공통 10음 규칙을 계약 테스트로 고정한다.
- 새 브라우저 전역 모듈의 로드 순서를 `studio.html`, 스모크 로더, 테스트 로더에서 함께 검증한다.

### 2. 음악 코어와 도화지 축 단일화

- `music-core.js`에 비공개 pitch-axis 모델을 두고 전체 15칸, 악기별 보이는 칸, 양방향 인덱스를 한 번만 계산한다.
- `drawableScale()`, `playableScale()`, `displayYFromStored()`, `storedYFromDisplay()`는 기존 시그니처를 유지하면서 같은 모델을 사용한다.
- `drawing.js`의 중복 필터링을 제거하고 코어 축 API에 위임한다.
- 서양 15칸, 국악 5종 10칸, 경계·왕복·숨은 파/시의 결정적 매핑을 테스트한다.
- 지속음 루프 검출을 RMS envelope, 안정 구간 선택, 초 단위 변환, 위상 정렬의 비공개 함수로 나눈다.
- 완전한 디지털 무음은 루프 구간을 만들지 않되, 매우 작은 실제 신호는 기존처럼 허용한다.

### 3. 오디오 계획과 노드 수명 분리

- 악기 미리듣기는 캐시가 준비되지 않았을 때 합성음을 즉시 한 번만 내고 샘플은 워밍만 하도록 해, 빠른 연속 클릭 뒤 오래된 음이 몰려 재생되는 경쟁 조건을 없앤다.
- DOM과 Web Audio에 의존하지 않는 샘플 선택·음 변환·stroke plan·구간 탐색 계산을 `audio-plan.js`로 옮긴다. 엔진의 기존 메서드는 얇은 호환 래퍼로 유지한다.
- transport와 preview 노드를 분리해 추적하는 `audio-node-scope.js`를 추가한다. 종료 콜백 보존, 중복 정지 안전성, 종료 노드 자동 제거를 행동 테스트로 검증한다.
- 합성 pad의 oscillator/filter/gain 그래프 생성만 `audio-pad-graph.js`로 옮기고, envelope·시작/종료·loop 정책은 호출부가 계속 소유한다.
- `AudioEngine`의 `isStarting`, `playGen`, pause/resume, timer와 `onState` 상태 머신은 이번 리팩터링에서 이동하지 않는다.

### 4. 스튜디오 공유와 내보내기 책임 정리

- 현재 마크업에서 도달 불가능한 내부 공유 카드·뷰어·삭제 UI와 무효 DOM 참조를 제거한다.
- `studio-share-ui.js`는 제거하되 `loadSharedChannel`, `publishSharedWork`, 갤러리 생성·관리과 `getStateSummary().sharedWorks` 호환 동작은 유지한다.
- `exportAudio`, `exportCover`, `exportDrawingImage`, `exportDrawingVideo` 워크플로를 `studio-export.js` 팩토리로 옮긴다.
- 테이크 선택과 공개 API 연결은 `studio.js`에 얇은 오케스트레이션으로 남긴다.
- 소스 문자열 위치를 검사하던 테스트는 출력 Blob·다운로드·상태 변화 행동 테스트로 바꾼다.

### 5. 스튜디오 transport 경계 분리

- 재생, 일시정지, 이어듣기, 정지, 플레이헤드, 무배경 시계, 배경 구간 재생을 `studio-transport.js` 단일 팩토리로 옮긴다.
- 공유 시간 상태를 여러 파일로 쪼개지 않고 한 컨트롤러가 소유한다.
- 설정 렌더러와 DrawingCanvas에는 늦게 연결되는 얇은 콜백을 주입해 순환 의존을 만들지 않는다.
- 배경만 재생, 무배경 재생, 탐색 후 재생, 일시정지·이어듣기, 재생 중 소리 드로잉, 끝 도달, 정지 초기화, 지우개 전 위치 동결을 가짜 시계·가짜 엔진 행동 테스트로 고정한다.

### 6. 문서 동기화와 최종 검증

- 새 모듈 책임과 실제 스크립트 로드 방식을 루트 및 `js/`의 `AGENTS.md`·`CLAUDE.md` 쌍에 동일하게 반영한다.
- README의 실제 내보내기 형식과 디버그 API 설명을 현재 구현에 맞춘다.
- 오디오 런타임 경계를 장기 규칙으로 남길 필요가 있는 부분은 ADR에 기록한다.
- 변경 파일 `node --check`, 단계별 단위 테스트, `npm test`, `git diff --check`, jsdom 통합 스모크를 수행한다.
- 로컬 서버에서 축 전환, 숨은 획 보호, 빠른 악기 미리듣기, 배경 탐색·일시정지, 소리 드로잉, 작품 게시, WebM·PNG 내보내기를 확인한다.

## 완료 기준

- 기존 테스트와 새 계약·행동 테스트가 모두 통과한다.
- 빠른 악기 미리듣기에서 한 클릭당 즉시 한 음만 나고, 이전 비동기 요청이 뒤늦게 재생되지 않는다.
- 국악기 5종은 동일한 10칸 축을 사용하고 서양↔국악 전환 뒤 저장 음높이가 보존된다.
- 완전 무음 샘플은 지속음 자동 루프 구간으로 판정되지 않는다.
- 오디오 계획 계산은 Web Audio 없이 테스트할 수 있고, 활성 노드는 transport/preview 범위별로 정리된다.
- 스튜디오에서 도달 불가능한 공유 UI가 제거되어도 게시와 갤러리 감상 흐름은 유지된다.
- 네 가지 내보내기와 transport 공개 API가 이전 이름으로 계속 동작한다.
- `npm test`와 통합 스모크가 통과하며 로컬 실행에서 새 콘솔 오류가 없다.

## 명시적 비대상

- 저장 레시피 스키마 변경
- 모바일 전용 UI 또는 브레이크포인트 추가
- `AudioEngine` transport 상태 머신의 별도 클래스화
- `channel.html` 갤러리 뷰어 재설계
- 외부에 공개된 적이 있는 `MusicCore` 함수의 제거

## 구현 결과

- pitch-axis 계산을 한 비공개 모델로 통합하고 `drawing.js`의 중복 필터를 제거했다.
- 지속음 루프 검출을 RMS 측정·안정 구간 선택·구간 변환으로 나누고 완전 무음 및 혼합 극미세 신호 경계를 보완했다.
- `audio-plan.js`, `audio-node-scope.js`, `audio-pad-graph.js`를 추가하고 `AudioEngine`은 기존 공개 메서드와 transport 상태 머신을 유지하는 facade로 정리했다.
- 샘플 준비 전 악기 미리듣기는 합성음을 즉시 한 번만 내며, `stop()` 뒤 비동기 미리듣기가 되살아나지 않도록 세대 토큰을 적용했다.
- 도달 불가능한 `studio-share-ui.js`와 관련 DOM/CSS를 제거하되 게시·갤러리·호환 QA API는 유지했다.
- 네 내보내기 워크플로를 `studio-export.js`로, 재생·플레이헤드·무배경 시계·배경 구간 상태를 `studio-transport.js`로 옮겼다.
- 배경 오디오 메타데이터의 오래된 콜백이 복원 구간을 덮지 않도록 세대와 `src`를 검증한다.
- 런타임 경계와 classic 스크립트 로드 순서를 ADR 및 현재 개발 문서에 동기화했다.
